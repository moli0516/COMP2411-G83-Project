| 20 November — PR #8           | A single data distribution did not illustrate how index usefulness changes with selectivity. | Added separate 100,000-action seed-like and selective benchmarks, comparing index-invisible and index-visible conditions. | Demonstrate workload-dependent optimizer choices and query performance.            | `tools/benchmark/`,`docs/index_benchmark.md`,`evidence/index_benchmark/`         |
| 21 November — commit`bb0420c` | Benchmark artifacts needed clearly named locations.                                          | Organized the two scenarios under`seed_like/`and`selective_like/`.                                                        | Align evidence paths with the two experimental populations.                        | `evidence/index_benchmark/seed_like/`,`evidence/index_benchmark/selective_like/` |

The retained seed-like run showed no demonstrated improvement: median time changed from 65.567 ms to 65.767 ms. The selective run improved from 33.732 ms to 4.668 ms, approximately 7.23-fold. These results illustrate that the index's benefit depends on the qualifying population and selected access path.

The benchmark changes index visibility rather than physically removing the index. It measures query execution and complete result fetching, while storage and write-maintenance costs are discussed separately.
